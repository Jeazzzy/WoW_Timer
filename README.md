# WoW Tracker — персональный Telegram-бот

Бот на **Python 3.12+ / aiogram 3 / SQLite** для 7 персонажей. Его можно запускать **локально из PyCharm**, VPS не нужен. Вся игровая логика использует **МСК (Europe/Moscow)** вне зависимости от часового пояса компьютера.

Версия с недельным трекером токенов и **ручным восстановлением таймера по оставшимся минутам**. Совместима с существующей базой `data/tracker.sqlite3` из предыдущих версий.

## Правила

- Игровые сутки: **07:00:00 МСК — 06:59:59 МСК** следующего календарного дня.
- У каждого из 6 персонажей — **суммарно 02:00** за игровые сутки. Перерывы сохраняются.
- Только один таймер может идти одновременно. Запуск другого чара автоматически ставит прежнего на паузу.
- Для **Инферналя** — **ручная отметка нормы** без таймера и без уведомлений.
- Когда норма готова, появляется кнопка **«🎁 Награда получена»**. У Инферналя — после ручной нормы.
- День персонажа полностью выполнен **только если выполнена норма И награда отмечена до 07:00 МСК**.
- В 07:00 начинается новый игровой день: таймеры и отметки наград за прошлый день больше не доступны. История сохраняет факт провала, если награда не получена вовремя. Никаких переносов наград.
- За **5 минут до двух часов** и **в момент завершения двух часов** приходят уведомления для 6 обычных персонажей.
- После 07:00 МСК отправляется отчёт за предыдущие игровые сутки.
- При сбое игрового сервера остаток времени можно установить вручную: на странице персонажа выбери **«⏱ Установить остаток (мин)»**, отправь число **0–120**. Исправление сохранится в SQLite; недельный прогресс и награды останутся на месте.
- Твоё обычное начало около 08:00 МСК не ограничивает бота: можно стартовать в любой момент после рестарта.
- 04:30 МСК — рекомендованное последнее начало длинной двухчасовой сессии с запасом до 07:00. Бот не запрещает более поздние сессии.

**Важно:** бот не подключается к WoW. Нажатия «Начать/Остановить» делаются вручную. Если забыть остановить таймер после выхода из игры, бот не сможет определить ошибку. **После перезапуска именно Telegram-бота** отсчёт продолжится по сохранённой отметке времени: предполагается, что персонаж оставался в WoW. Никаких дополнительных подтверждений после перезапуска не требуется. Если из-за вылета WoW или выключения компьютера набежало лишнее время, используй «Установить остаток (мин)».

## Ручная корректировка таймера при падении сервера WoW

Если WoW упал и бот продолжал считать время, корректируй таймер **после восстановления сервера и возвращения на персонажа**:

1. `/start` → выбери нужного персонажа (кроме Инферналя).
2. Нажми **«⏱ Установить остаток (мин)»**.
3. Ответь одним числом, сколько **минут осталось до 2 часов**, например `37`.
4. Бот поставит прогресс этого персонажа на `01:23/02:00` и **с момента получения числа** запустит таймер ещё на 37 минут. Предыдущий ошибочный прогресс будет **заменён**, а не добавлен.

Можно ввести от `0` до `120` целых минут: `0` = время нормы выполнено сразу (награду всё равно нужно забрать и отметить до 07:00 МСК); `120` = начать двухчасовую норму заново. `/cancel` — отменить ввод без корректировки.

Если запускается положительный остаток, таймер другого персонажа автоматически ставится на паузу; его ранее учтённые минуты сохраняются. При `0` другой таймер не прерывается. Предупреждение за 5 минут и сообщение о выполнении нормы продолжат работать. При остатке менее 5 минут бот **не** будет присылать некорректное сообщение «осталось 5 минут», но уведомит о выполнении нормы.

Если к игровому сбросу в 07:00 МСК времени не хватит на завершение и получение награды, бот предупредит об этом. Старая норма/награда не переносится в следующий день. Исправление недоступно после отметки награды и для Инферналя (у него своя ручная кнопка).

Если перезапустится **сам процесс Telegram-бота** — локально в PyCharm или позднее на VPS — таймер восстановится из SQLite автоматически и учтёт прошедшее время. Бот не знает, был ли персонаж онлайн во время его простоя; при необходимости поправь остаток вручную.

## Недельный КД, токены и выкупы

- Недельный КД: **среда 07:00 МСК → следующая среда 07:00 МСК**, то есть **семь игровых суток** со среды по вторник включительно.
- У **каждого** персонажа свой отдельный прогресс `0/7` … `7/7`. За `7/7` начисляется **+100 токенов на этого персонажа** при недельном сбросе. Полная неделя семи персонажей — **+700 токенов**.
- Обычный день закрыт только если получена награда после 2 часов онлайна **до 07:00 МСК**. Для Инферналя — ручная отметка нормы плюс награда.
- Пропущенный/незакрытый день **конкретного персонажа** можно компенсировать выкупом **−50 токенов**. Выкуп **не** закрывает этот день у остальных шести персонажей.
- Бот **не совершает покупку в WoW**: сначала выкупи день в игре, затем в `/week` нажми на персонажа → «Отметить выкуп» → подтверди. Указанный расход фиксируется в расчётах только один раз.
- Выкуп доступен для **уже завершившихся** игровых дней **текущей недели** до недельного сброса. Покупки за предыдущие недели бот не позволяет добавлять задним числом.
- В `/week` показываются отдельные `0/7` для каждого персонажа, прогноз бонуса **при выполнении остальных дней**, текущие расходы, итог недели с учётом расходов и вариант «если выкупить все пропуски».
- Укажи свой **фактический** текущий баланс токенов командой `/balance 250` (где 250 — пример). Бот будет вычитать отмеченные выкупы и прибавлять начисленные недельные бонусы. Если потратишь или получишь токены **вне бота**, снова используй `/balance <актуальная сумма>` для сверки.
- Начисления в боте **учётные**, не автоматическое получение валюты в игре. При каждом сбросе в среду бот отправляет недельный отчёт; история и транзакции остаются в SQLite.

Примеры: если все 7 персонажей закрыли по 7 дней без выкупа, итог недели **+700**. Если у Эдгвина один день пропущен и выкуплен, а все остальные дни всех персонажей закрыты, итог **+650** (+700 вознаграждений, −50 выкуп). Если Эдгвин пропустил день **без** выкупа, бонус у него **0**, а остальные шесть дадут **+600**.

**Принятые для этой версии допущения:** недельный сброс происходит именно в среду в 07:00 МСК; выкуп заменяет любой один пропущенный день у конкретного персонажа; количество покупаемых дней на персонажа не ограничено самим ботом; токены учитываются как **общий баланс аккаунта**. Если у игровой механики есть ограничения на число выкупов или баланс индивидуален у каждого персонажа, расчёт нужно будет адаптировать.

## Быстрый запуск локально в PyCharm (Windows)

**Сервер и Docker не нужны.** Пока открыт процесс `bot.py` на твоём компьютере, бот принимает нажатия и присылает уведомления. Если PyCharm/ПК выключен, Telegram-бот не отвечает и уведомлений нет; после повторного запуска он восстановит данные из SQLite и пересчитает незакрытые таймеры по времени запуска.

1. Распакуй архив в папку, например `C:\Projects\wow_tracker_bot` (важно открывать в PyCharm именно распакованную папку).
2. Создай Telegram-бота через [@BotFather](https://t.me/BotFather), возьми токен. Узнай свой **числовой** Telegram ID, например у [@userinfobot](https://t.me/userinfobot).
3. В папке проекта скопируй файл `.env.example` в `.env` (точка перед `env` важна; на Windows включи показ расширений файлов). В файле `.env` укажи свой `BOT_TOKEN` и `OWNER_ID`, например:

   ```dotenv
   BOT_TOKEN=123456789:ТВОЙ_ТОКЕН_ОТ_BOTFATHER
   OWNER_ID=123456789
   DB_PATH=data/tracker.sqlite3
   ```

   Значения здесь **пример**, вставь свои. Токен не публикуй и не присылай никому.

4. Открой папку проекта в PyCharm. В **Settings → Project → Python Interpreter** выбери или создай виртуальное окружение `.venv` на Python **3.12 или 3.13** (если PyCharm предложит создать Virtualenv автоматически, соглашайся).
5. В терминале PyCharm выполни (в `requirements.txt` уже включена база часовых поясов `tzdata` для Windows):

   ```bash
   python -m pip install -r requirements.txt
   python bot.py
   ```

   Если терминал использует не тот Python, установи зависимости командой `.venv\Scripts\python.exe -m pip install -r requirements.txt`, а затем запусти `.venv\Scripts\python.exe bot.py` (это команды для Windows).

6. В Telegram открой созданного бота, нажми **Start** и отправь `/start`. Увидишь список из семи персонажей и кнопки управления. **Не закрывай терминал**, пока бот нужен.

**Проверка без Telegram:** `python -m unittest discover -s tests -v` — тестирует игровую логику. Когда закончишь пользоваться ботом, останови его в PyCharm (`Stop` или `Ctrl+C`). При новом запуске данные останутся в `data/tracker.sqlite3`. Если позже перенесёшь бота на VPS, перенеси также папку `data/`. Не запускай одновременно два экземпляра с одним токеном.

## Запуск на VPS (Docker Compose)

Потребуется VPS с установленными Docker Engine и Docker Compose, например Ubuntu 24.04. В папке проекта на сервере:

```bash
cp .env.example .env
# отредактируй .env (BOT_TOKEN + OWNER_ID)
docker compose up -d --build
docker compose logs -f
```

Бот работает через long polling, открывать порты и настраивать домен или HTTPS не нужно. `restart: unless-stopped` перезапускает его после сбоя; база хранится в `./data/` и не стирается при обновлениях. **Не запускай одновременно локальный и серверный экземпляры с одним токеном.**

Обновление на VPS:

```bash
git pull
docker compose up -d --build
```

Резервное копирование: регулярно сохраняй каталог `data/`. Для согласованного копирования SQLite лучше на время резервного копирования останавливать бота или использовать команду SQLite `.backup`.

## Команды

- `/start`, `/status` — сводная панель, переход к персонажам;
- `/rewards` — отдельное окно наград;
- `/history` — результаты последних 7 игровых суток;
- `/week` — недельный прогресс по 7 персонажам, прогноз токенов, отметки выкупов;
- `/balance` — показать учётный баланс, `/balance 250` — синхронизировать с фактическим балансом в WoW;
- `/cancel` — отменить запрос оставшихся минут (не меняя текущий таймер);
- `/help` — подсказка.

## Проверка логики

Без Telegram/сервера можно запустить тесты:

```bash
python -m unittest discover -s tests -v
```

**Обновление с предыдущей версии:** не удаляй каталог `data/`. Просто замени файлы проекта новой версией и повторно запусти `docker compose up -d --build`. Новые таблицы токенов создаются в существующем файле SQLite автоматически. Система недельного начисления запускается с недели, в которую ты впервые включишь эту версию; прошлые недели автоматически не награждаются.

Не отправляй токен бота другим людям и не добавляй `.env` в репозиторий.
